Notices for the libraries inside ffmpeg.exe and ffprobe.exe

What this file is
-----------------
The complete package ships ffmpeg.exe and ffprobe.exe from BtbN's static
Windows build ffmpeg-n9.0.2-14-gebafaee10a-win64-gpl-9.0.zip (GitHub release
autobuild-2026-09-29-13-10 of https://github.com/BtbN/FFmpeg-Builds, SHA-256
11f676f2ee62c39768cef1892e2e171adf00fd04c85620b771520e985e7c7a69). That release
was built from FFmpeg-Builds commit
6c9aec5fc9a72ec3abedd1fa84db141fa18cf52b
for the win64 target, gpl variant and 9.0 addin. Besides FFmpeg itself, the
two executables contain every library that build enables and the libraries
those depend on. The executables as a whole are conveyed under the GNU General
Public License version 3: see ffmpeg.txt and ffmpeg-GPL-3.0.txt beside this
file. Many of the libraries inside them are under permissive licenses (BSD,
MIT, ISC, zlib, Apache-2.0 and similar) that ask for their copyright and
license notices to travel with binary copies. This file collects those
notices. Libraries under the GPL, LGPL or MPL are only named, in the closing
section.

How the list was made
---------------------
Each file in scripts.d of FFmpeg-Builds at that commit builds one dependency
and pins its source with SCRIPT_REPO and SCRIPT_COMMIT (or SCRIPT_REV for the
two Subversion checkouts). Every script was evaluated for TARGET=win64,
VARIANT=gpl with the 9.0 addin; its ffbuild_enabled decides whether the
dependency is built, and the FFmpeg configure line (`ffmpeg -buildconf`) and
each library's pkg-config dependencies decide what is linked. Version strings
and source paths inside the shipped ffmpeg.exe were used to confirm the
result; ffprobe.exe contains the same set. Built but not linked: SDL2 (only
ffplay.exe, which is not shipped, uses it), zstd, and the libcurl helpers
nghttp2, nghttp3, ngtcp2 and libpsl (libcurl itself is off for the 9.0
build). SPIRV-Cross (commit aa217aeb6c9f0ace7a0ab233b28807edf45eb165)
is built for libplacebo's Direct3D 11 backend, which FFmpeg does not call, and
none of its code shows in the binary; it is Apache-2.0, so the Apache License
text below covers it either way.

Each notice is taken from upstream at the commit named in its section and is
unaltered apart from line endings. Where only part of a file applies (the
license section of a README, the attribution part of a NOTICE file, the header
of a source file) the section says so, and source-file headers have their
comment markers removed. Where a library is offered under a choice of licenses
that includes the Apache License 2.0, the section says that this distribution
takes it under that license.

fontconfig/src/ftglue.[ch]

/* ftglue.c: Glue code for compiling the OpenType code from
 *           FreeType 1 using only the public API of FreeType 2
 *
 * By David Turner, The FreeType Project (www.freetype.org)
 *
 * This code is explicitely put in the public domain
 *
 * ==========================================================================
 *
 * the OpenType parser codes was originally written as an extension to
 * FreeType 1.x. As such, its source code was embedded within the library,
 * and used many internal FreeType functions to deal with memory and
 * stream i/o.
 *
 * When it was 'salvaged' for Pango and Qt, the code was "ported" to FreeType 2,
 * which basically means that some macro tricks were performed in order to
 * directly access FT2 _internal_ functions.
 *
 * these functions were never part of FT2 public API, and _did_ change between
 * various releases. This created chaos for many users: when they upgraded the
 * FreeType library on their system, they couldn't run Gnome anymore since
 * Pango refused to link.
 *
 * Very fortunately, it's possible to completely avoid this problem because
 * the FT_StreamRec and FT_MemoryRec structure types, which describe how
 * memory and stream implementations interface with the rest of the font
 * library, have always been part of the public API, and never changed.
 *
 * What we do thus is re-implement, within the OpenType parser, the few
 * functions that depend on them. This only adds one or two kilobytes of
 * code, and ensures that the parser can work with _any_ version
 * of FreeType installed on your system. How sweet... !
 *
 * Note that we assume that Pango doesn't use any other internal functions
 * from FreeType. It used to in old versions, but this should no longer
 * be the case. (crossing my fingers).
 *
 *  - David Turner
 *  - The FreeType Project  (www.freetype.org)
 *
 * PS: This "glue" code is explicitely put in the public domain
 */
